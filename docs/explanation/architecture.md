## 核心设计原则

### 1. 多数据源自动切换

价格数据采用"优先级链"策略：对每只股票依次尝试可用数据源，直到成功返回数据。

- **美股**: 腾讯财经 API（优先）→ yfinance（备选）
- **A股**: akshare（优先）→ yfinance（备选）
- **港股**: akshare（优先）→ yfinance（备选）
- **韩国股**: Naver Mobile API（优先）→ yfinance

参见 `price_data.py` 中的 `fetch_price_history()` 函数。

### 2. 缓存第一

所有外部 API 数据先写入 SQLite 缓存，下次读取时优先返回缓存数据。即使用户离线或 API 故障，仪表盘仍可展示上次成功拉取的数据。

- `PriceCache` 表缓存历史价格
- `StockInfoCache` 表缓存公司信息（JSON 字段）
- `IndicatorObservation` 缓存指标观测值

### 3. 产业链中心的数据模型

不是以"公司"而是以"产业链环节"为中心组织数据。每家公司通过 `CompanyChainLink` 关联到 1 个或多个环节，支持多角色标注（如三星既在存储芯片又在晶圆代工）。

### 4. 两代估值模型并存

| 特性 | v1 (Gordon Growth) | v2 (供需感知未来PE) |
|------|-------------------|-------------------|
| 方法论 | DCF 两阶段折现 | 未来 PE 倍数法 |
| 核心输入 | 增长率、净利率、折现率 | 增长率、供需分数 |
| 供应端感知 | 无 | 供应链供需缺口 → 调整增长假设 |
| 输出 | 公允PE、公允市值、上涨空间 | 未来PE、估值信号(低估/高估) |
| 最佳用途 | 行业中性估值 | 周期性行业、供需拐点 |

参见 `docs/explanation/valuation.md`。

### 5. 产业情报的信号系统

14 个行业数据采集器定时抓取公开数据（ASML/NVIDIA/TSMC 官方 IR、TrendForce、WSTS/SIA 等），结合 MiniMax AI 自动生成边际变化解读，经 Tier 分层（P0/P1/P2）推送给用户。

### 6. 启动即用的幂等迁移

`startup_migration.py` 在服务启动时自动运行，确保新增公司（如 SNDK、WDC）的关注和产业链关联存在。只操作数据库，不调用外部 API，避免影响 Zeabur 健康检查。

## 核心模块说明

### 启动时序

```
main.py startup
  ├── 检测数据库是否存在
  ├── run_startup_migration()    ← 幂等写入 SNDK/WDC 等
  └── init_scheduler()           ← 启动 6 个定时任务
       ├── 产业采集  6:00/18:00
       ├── 价格刷新  每15分钟
       ├── 财务刷新  7:00/19:00
       └── 涨跌幅刷新 每4小时
```

### 数据采集分层

```
Layer 0: 实时行情（15分钟级）
  腾讯 API → StockInfoCache

Layer 1: 财务数据（半日级）
  yfinance → Financial + StockInfoCache

Layer 2: 行业数据（半日级）
  14 采集器 → KeyIndicator + IndicatorObservation → MiniMax AI 分析

Layer 3: 宏观数据（日级）
  FRED API + tedata → KeyIndicator + IndicatorObservation

Layer 4: 历史价格（按需回填）
  Tencent Kline API → PriceCache → MarketData
```
